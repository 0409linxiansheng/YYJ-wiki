说实话，ERPNext 的官方文档不算差，看着挺全。

但它默认了几件事：你能顺畅访问 GitHub、你的服务器能正常下 pip 和 npm、你分得清 bench / Docker / Pilot 到底该用哪个。

这三条，在国内经常同时不成立。

我第一次装的时候就是：复制第一条命令，等半天，Docker 克隆源码那步开始超时，然后就没有然后了。

## 卡住人的第一个地方：网络

这大概占了一半以上的失败。

- 源码在 GitHub 上，克隆动不动就断
- pip、npm、apt 用官方源，速度能低到几十 KB/s
- 最要命的是有几个依赖，**地址直接写死在 GitHub 上**，你换镜像都换不掉

所以十次装不上，八次不是命令敲错了，是网的问题。

解决办法就两条：要么折腾代理，要么用一份已经把源和依赖都改好的安装方案 —— 我后来走的是第二条。

## 第二个地方：装法太多，不知道选哪个

现在常见的有三种：

- **bench**：老牌方式，网上教程最多，跟着走能看见每一步在干什么
- **Docker**：打包成容器，干净，但出问题的时候不好查
- **Pilot**：Frappe 官方新的部署工具，bench 的继任者，目标是少折腾

新手翻车最多的情况，不是选错，是**混着看**：跟着 A 教程装了一半，卡住，又翻到 B 教程，结果两边对不上，越装越乱。

我的建议只有一句：**选一种，从头走到尾。** 装成了再研究别的。

## 第三个地方：其实装完才刚开始

很多人看到登录页面就以为结束了。其实还有三件事没做，系统基本没法用：

1. **中文**。界面全是英文，得装语言包、切时区、改货币
2. **域名和 HTTPS**。只用 IP 访问，邮件、支付、部分浏览器功能都会受限
3. **备份和升级**。不备份，出事就是全丢；不会升级，装完是什么版本就永远是那个版本

## 我被这些坑烦到，然后写了几个东西

都是公开的，随便用：

**先说最重要的：[pilot-cn](https://github.com/YYJ-lin/pilot-cn)**

就是上面说的"第二条路"。我把 Frappe 官方的 Pilot 改造了一版，专门对付国内网络那堆问题：GitHub 依赖处理掉、慢源换掉，目标是**在国内网络环境下一次装成**。装完能中文、能升级、能装任意来源的应用。

README 写得比较细，从"在新服务器上从零装一套"开始，包括装完的地址和密码在哪、密码忘了怎么改、怎么升级、怎么回滚、常见问题。你要是第一次装，照着一路走就行。

**然后是中文：[YYJ_translate](https://github.com/YYJ-lin/YYJ_translate)**

ERPNext 界面那些英文是真的多。这个东西的思路是：把所有 app 里能翻译的词条扫出来，汇成一份清单，你只填还没翻译的那部分，回填之后自动编译生效。现在攒了 4800 多条译文。

**另外两个，看需不需要：**

- [erpnext-wiki](https://github.com/YYJ-lin/erpnext-wiki)：Frappe Wiki 的中文定制版，界面中文优先，加了公式、代码片段、语音输入这些
- [helpdesk](https://github.com/YYJ-lin/helpdesk)：Frappe Helpdesk 的中文化分支，要做售后工单的可以看看

## 如果让我给一条最短的路

1. 弄一台服务器，Ubuntu，配置要求见 pilot-cn 的说明【待你验证：写清最低配置，比如 2 核 4G、Ubuntu 24.04】
2. 按 pilot-cn 从零装一套，装完把给你的几个密码记下来 —— **真的记下来，忘了很麻烦**
3. 上 YYJ_translate，界面换成中文
4. 先别急着开模块，把「客户 → 订单 → 库存」这条线走通

## 装的时候可能遇到的，先给你对个号

- **克隆卡住、超时** → 网络到 GitHub 不通，用 pilot-cn 或配代理
- **pip / npm 慢到怀疑人生** → 官方源，换国内源
- **装完打不开网页** → 先看进程起没起，再看防火墙端口放没放
- **界面全英文** → 没装语言包，装 YYJ_translate，顺手把时区改了
- **管理员密码忘了** → pilot-cn 里有一节专门讲四个密码分别怎么改
- **想升级又怕搞坏** → 先备份，再看「升级与回滚」那节
